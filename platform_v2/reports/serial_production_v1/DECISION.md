Any absent/uncertain return, consumed entry, failed importer or missing pair holds and prevents next entry. No scientific replay is performed.
4. Production blockers are authorization/install-state qualification, GPU-consumer exclusion, and real authorized first-entry qualification. Two enabled V1 tasks remain installed, so V2 is not yet the sole installed automatic executor. Two Ansys Electronics Desktop processes appear in the WDDM GPU census with N/A memory; only licensing children were found. Their GPU computation status is not proven; neither is terminated. Historical stdin text and stale V1 control markers do not gate V2.

## One state chain

Frozen queue + source + explicit release → local single worker token/fence → Coupling immutable conservative entry evidence → atomic existing Coupling count update → V2 SQLite mirror → Coupling immutable nonrepeatable launch marker → V2 LAUNCH_REQUESTED → native launcher/engine PID + creation + FSP binding + persistent log → complete native FSP and sibling folder/H5 archive + SHA → independent fresh LOAD of complex E/H, coordinates, 21 wavelengths and frozen phase references → frozen scientific decoder → actual load_verified_runner_case → durable 609-output labels → atomic exclusive Coupling label/ingest publication → Coupling truth/label counts → V2 TRUTH_VALID and slot release → next authorized eligible case.

Coupling owns authorized case/attempt and budget. Its adjacent write-ahead evidence is part of that authority, not an allocator or a new budget DB. V2 SQLite owns only local execution state. A crash between the receipt and Coupling ledger write leaves a conservative hold; reconcile_entry_evidence repairs the count monotonically without invoking any solver. A lost/restored V2 SQLite cannot repeat an already marked launch. No entry is refunded.
